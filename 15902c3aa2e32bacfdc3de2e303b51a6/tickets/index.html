Integration

CORE-01IntegrationMVP

Oracle - hour-registration integration

Pull actual hours booked per application so the platform can compute hour-based cost (Actuals) and productivity. Oracle is the financial system of record for time.

Source: Oracle · API/export · per sprint/PI

Data fields

  • application id (mapping to Core4 app)
  • period (sprint / PI)
  • person or role
  • hours booked
  • cost centre (optional)

Acceptance

  • ✓Hours aggregated per app per period
  • ✓Feeds Actuals (hour model) and Productivity (h/FP)
  • ✓No double-count with Jira time logging

Depends on: CORE-11

CORE-02IntegrationMVP

Jira - agile flow & incidents integration

Single Jira integration feeding two data products: (a) agile flow metrics, and (b) incident tickets for MTBF/MTTR (open/close timestamps on a dedicated incident issue type/label).

Source: Jira · REST API · per sprint/PI (flow) + continuous (incidents)

Data fields

  • Flow: issue key, issue type, story points (committed & realized), sprint/PI, status, created/updated/resolved dates, assignee
  • Mapping: Jira project to Core4 application
  • Incidents: incident issue type/label, opened (failure) timestamp, restored/closed timestamp, severity

Acceptance

  • ✓Velocity, Load, Flow predictability derived from flow data
  • ✓MTBF and MTTR derived from incident open/close timestamps
  • ✓Incident definition (issue type/label + which timestamps) is configurable

Depends on: CORE-11

Upload

CORE-05UploadMVP

FPA Excel - upload & ingestion

Upload the certified counter's workbook (one row per counted function). This is the scope/cost/time backbone. Versioned snapshots; de-dup by identifier.

Source: Upload (Excel/CSV) · per count (weekly/monthly/PI)

Data fields

  • identifier
  • FPA name (e.g. 2.1.4.2 - Flights - Creation - Handler setting)
  • type (IFPUG EI/EO/EQ/ILF/EIF - depends on configured method)
  • #FP
  • complexity (Low/Medium/High)
  • status (Open / DoR / DoD / Tested / Deployed)
  • date DoR, date DoD, date Tested, date Deployed
  • paid (yes/no)
  • cost (EUR)

Acceptance

  • ✓Schema validation with clear errors
  • ✓Snapshot kept for audit/baseline comparison
  • ✓Drives Delivered/Remaining FP, throughput, Cost/FP, scope variance

Depends on: CORE-11, CORE-17

Engine

CORE-11EngineMVP

Derivation & forecast engine

The calculation core: Delivered/Remaining FP, throughput, delivery speed, productivity, forecast (due) date, Cost/FP, and Actuals, ETC, EAC and VAC for cost, time and scope. Honours the contract-type toggle.

Data fields

  • inputs: FPA rows, Oracle hours, rate card, price book, baselines, contract type
  • outputs: all Cheaper / Faster / Scope metrics + forecast variances

Acceptance

  • ✓Hour vs FP cost models switch correctly per project
  • ✓ETC = estimate (hour) / agreed (FP)
  • ✓Scope VAC reflects new FPA rows as scope growth
